# 特殊キーの初回キー2割当（0.3.41）

原因: 空配列のindex1へキーを代入するとindex0がholeになる。行の編集判定で配列を展開し、undefinedにtoUpperCaseを呼ぶことでReactの描画が例外終了していた。

修正: キー配列を常に左詰めにする。空行のキー2からの入力はキー1へ配置。キー1を解除するとキー2を繰り上げる。別行へキーを移動した場合も元行を詰める。編集判定と値変更に渡すキーも正規化して空欄・holeを除く。

回帰テスト5件:

- FPS/FOVの空行にキー2から初回割当し、holeが発生しない。
- キー1解除時の繰り上げ、各スロット置換、解除後の再割当。
- プリセット間の移動、元行の左詰め、値と元キー情報の保持。
- 旧状態のhole・空文字に対する正規化。
- キー2からの初回割当後の値変更・解除と編集件数の整合性。

ブラウザーの匿名FixtureではFPSキー2にQ、FOVキー2にEを割当し、どちらもキー1に表示されることを確認。FPSキー2にRを追加し、キー1/Qを解除するとRがキー1へ移る。その後のFPS165への値変更、ESCでの入力キャンセル、編集全キャンセル（キー4枠空・変更0件・編集マーカー0件）を確認。ブラウザーのエラーログ0件。画像: special-slot-fix-preview.png。
