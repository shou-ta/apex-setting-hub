# バックアップ管理（0.3.40）

復元時の自動バックアップを削除。復元元3ファイルをすべて読んでから書き込み、失敗時はメモリ上の現在値・属性へ戻す。復元では保持上限の整理も行わない。

manifestにnameとlockedを追加し、古いmanifestでは空名・未ロックを既定値にする。名前は表示用でID・保存ディレクトリ・復元参照は変更しない。名前変更とロック更新は現在の設定フォルダに属するバックアップのみ許可。名前は100文字以下、制御文字を拒否する。

保持数はロック済みを除いた最新20件。ロック解除だけでは削除せず、次のバックアップ作成時に通常の整理対象になる。ロック済みは数の上限に含めない。

検証:

- 同一バックアップを2回復元しても件数1のまま。
- 復元元の1ファイルがない場合、現在の3ファイルを変更しない。
- 通常24件から古い2件をロックし、整理後はロック済み2件＋通常20件。名前も保持。
- ロック解除後の整理、無効ID・制御文字の拒否、旧manifestの互換性を確認。
- ブラウザーの匿名Fixtureで名前変更・ロック・解除と件数表示を確認。backup-lock-preview.png。
- Rust35件、JavaScript27件成功。実際のApex設定への書込みは実施していない。
